# v0.4.2 검증 현황 (2026-10-11)

## 진행한 것

- 기존 v0.4.1 소스에서 시작하여 `field-validate` 명령어 구현
- MCAP/DB3 개별 분석, 파일 크기/SHA-256/토픽/이벤트/수행시간 기록
- 메시지 처리량 제한, 미지원 타입, 불명확한 토픽 선택, 디코딩 문제를 검토 항목으로 표시
- 선택적으로 **사람이 사전에 작성한** 장애 코드 + 시간대 라벨과 매칭해 해당 라벨의 검출률 계산
- JSON / Markdown 검증 요약 파일과 개별 HTML 보고서 생성
- 기존 테스트 포함 전체 회귀 테스트 수행

## 하지 못한 것 (중요)

- JKK 등의 외부 실측 MCAP/DB3 **원본 파일 다운로드 실패**: 실행 환경의 네트워크 제한
- 따라서 외부 실제 로봇 기록에 대한 정상 동작, 검출 정확도/재현율, 오탐률은 **미검증**
- 현업 해외 엔지니어 인터뷰 및 구매의향 확인도 미진행

## 결과 해석

- `READY_FOR_HUMAN_REVIEW`: 이번 룰의 핵심 커버리지 경고가 없었다는 뜻이지 올바른 장애 진단이라는 뜻이 아님
- `REVIEW_REQUIRED`: 미지원 타입/모호한 역할/일부 메시지 누락/빈 분석 같은 문제를 확인해야 함
- 시간적으로 인접한 이상 신호가 보인다고 인과관계나 근본 원인이 증명되는 건 아님
- 정상 데이터에서 탐지 알람이 없다는 것을 로봇이 정상이라고 증명했다고 해석하지 말 것
- 가상 데이터에서 라벨 검출률이 높아도 실제 현장 정확도를 의미하지 않음

실제 공개 데이터는 `docs/FIELD_PILOT_EN.md`의 원본 출처에서 사용자가 자신의 Ubuntu PC에 다운로드한 뒤 `field-validate`로 독립 실행할 수 있다. 고객/회사 로그는 반출하거나 채팅에 공유하지 말고 승인된 데이터만 사용해야 한다.
