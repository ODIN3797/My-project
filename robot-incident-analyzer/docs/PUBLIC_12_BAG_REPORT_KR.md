### 제품 결함 발견 후 수정

기존 자동 탐색이 GPS 속도 토픽 `/rpsc4/global_position/raw/gps_vel`을 명령 `cmd_vel`과 비슷한 CDR 형식이라는 이유만으로 **모터 구동 명령으로 잘못 선택**하던 문제를 실제 Vigo 기록에서 발견했다. 이를 수정해 이제 명령 의미가 충분히 분명한 `cmd_vel`/`velocity_cmd` 등의 이름만 자동 선택한다. 실제 재검증에서 **Vigo 9개 파일 모두 GPS 속도→명령 자동 매핑 0건**을 확인했다. 수동 강제 지정은 경고와 함께 가능하다.

### 현재 한계

- Vigo는 `mavros_msgs/msg/Mavlink`, `GPSRAW` 등 **최소 9종 커스텀/미지원 메시지 타입의 payload를 해석하지 못한다.** 타임스탬프와 토픽 집계 위주.
- Odometry의 좌표 프레임이 바뀌거나 GNSS 기반 위치가 갱신되어 나타난 점프인지, 실제 제어 실패인지 확인하려면 원본 데이터와 기준 좌표 검토가 필요하다.
- 배포된 분석기는 로봇별 목적·제어 의미를 자동으로 알지 못한다. 커스텀 메시지 스키마와 명시적인 역할 지정이 필요할 수 있다.
- Zenodo에서 정상 로그의 위치 점프 이벤트 2건도 실제 오탐이라고 판정할 근거가 없다.

## 5. 상용화 전 권고사항

1. **정답 장애가 있는 로그 확보:** 고장 발생/종료 시각과 원인이 검증된 최소 20건.
2. **동일 작업 조건의 정상 기준 확보:** 위치추정/도킹/정지/충전 단계별 기준 모델. 주파수 변화는 작업 단계에 의해 발생할 수 있다.
3. **진단 성능 평가:** 라벨 별 재현율, 정상 시간당 오탐, 원인 후보의 top-3 정확도, 검출 지연.
4. **Vigo의 Odometry 위치 점프 3건과 Zenodo 정상 파일의 점프 2건을 수동 검수**하고 오탐 규칙을 개선.
5. **해외 엔지니어 5명 사용성 검증:** Foxglove/PlotJuggler 대비 장애 조사 소요시간을 블라인드 비교.

이 검증은 **외부 기록 12개에 대한 형식 호환성 및 기준 대비 메시지 주기 비교의 성공**이지, 로봇 장애 원인 판정 정확도의 증명이 아니다.
